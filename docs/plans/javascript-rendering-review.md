# Browser rendering review — first round

Reviewed the uncommitted implementation against `9031fe8757a64ea5978372348a8b717f7ee15ca7` and `javascript-rendering.md`, jointly with calmtoad-eng2. Not ready to ship. No release/version/commit/push authorized by this review.

## Spec and correctness findings

1. **P1: missing source evidence can become a false clean result.** `src/render.rs:861-900` skips initial HTML without a known small Content-Length. `src/indexability.rs:262-265` and `src/crawl.rs:1723-1736` still treat the capture as complete. An actual Chrome fixture with source `<meta name=robots content=noindex>` removed by JS, served without Content-Length, produced `NoBlockFound`, `noindex=false`, `complete=true`, `source_captured=false`. This violates “Incomplete render/source evidence must not become No block found.” Capture bounded source without trusting Content-Length where possible; propagate an explicit source capture state when missing, failed or capped. Do not infer completeness by parsing explanation text. Test chunked/no-length and encoded/oversized bodies, including source restrictions removed by JS, across assessment, sitemap and exports.

2. **P1: canonical changes are assessed as simultaneous conflicts.** `src/crawl.rs:1487` retains both stages, but `src/indexability.rs:655-671,1056-1066` combines targets across stages. Actual browser source `/old` changed to rendered `/new` produced both `CanonicalConflict` and `CanonicalChanged`, labeled `ReviewCanonical`. Spec explicitly says a replacement “is a change across captures, not automatically two simultaneous conflicting declarations.” Assess current rendered declarations separately from historical source evidence. Cover replacement, removal, addition, multiple declarations within each stage, and malformed source replaced by valid rendered canonical; preserve truthful source observations.

3. **P1: same-document URL changes audit the wrong URL.** `src/render.rs:972-976` only updates observed_url on History API navigation. Actual fixture calling `history.replaceState(null,'','/changed/path')` was still `Captured`, complete, `NoBlockFound` under the original requested URL with no queued transition. `src/crawl.rs:1429-1469` resolves its relative links/canonicals against the original URL. Spec says “Do not audit the destination's DOM as the original URL.” Handle meaningful same-document path/query transitions explicitly, preserve requested/observed URL, mark interrupted appropriately, and admit a destination through policy/budget without inventing HTTP redirects. Test relative links/canonicals, replaceState/pushState, fragment-only changes and loops.

4. **P1: custom Chrome switches are malformed.** `src/render.rs:396-413` passes strings already prefixed with `--` into chromiumoxide's Arg conversion, which prefixes `--` itself. Actual process command contained `----deny-permission-prompts`, `----disable-background-networking`, etc. These switches do not implement their intended settings. Use proper key/value Arg construction, inspect the actual command, retain sandbox/TLS, and test policy behavior rather than only the configured string. Some headless/extension flags are separately supplied by the library; do not assume every setting is absent or working.

5. **P1: cancellation/deadline/cleanup boundaries omit browser operations.** `src/render.rs:339-345` version probing is an unbounded subprocess output wait; setup/context/page creation at `602-623` occurs before capture_page's deadline; shutdown at `531-535` awaits close/wait before kill with no bound. DOM extraction at `1082,1211` selects only its deadline, not cancellation. Spec requires bounded shutdown and Stop during startup/navigation/settle/extraction. Make the whole owned lifecycle bounded and cancellable, including setup/probe/extraction and app close; kill/wait only owned children on a bounded graceful-close fallback, dispose failed contexts, and remove profiles. Browser job probes reported elapsed times 32,038ms and 22,344ms despite the 15-second configuration; some phases sit outside the deadline. These timings do not by themselves prove a hung shutdown. Add failure-path tests, including hung evaluation, failed startup/crash and application exit; no unrelated browser termination.

6. **P1: advertised byte/resource guardrails are not enforced as stated.** `src/render.rs:1204-1227` uses JavaScript UTF-16 length/slicing for a UTF-8 byte cap and materializes the entire outerHTML before slicing. An actual UTF-8 fixture returned **1,200,039 bytes**, `rendered_truncated=false`, `state=Captured`, with a 1,000,000-byte limit. Bound acquisition/serialization and enforce bytes, including Unicode. Source GetResponseBody can also decompress an arbitrarily large body despite a small compressed Content-Length before truncation. `src/render.rs:992-1002` accounts transfer only at LoadingFinished, so a large/never-ending in-flight response can pass the transfer cap before completion. Track streaming transfer and stop at the cap, account for failures and incomplete essential resources, and test oversized/compressed/chunked/never-finishing fixtures. The limits are guardrails, but must meaningfully stop resource work before an unbounded body is collected.

7. **P2: incomplete Browser captures can receive ordinary content audit results.** `src/crawl.rs:1723-1738` falls back to source HTML when rendered DOM is unavailable; `auditable` at `692` ignores capture completeness. A timed-out Browser page can therefore contribute source titles/headings to duplicate calculations and content CSV can say OK without capture provenance. Spec requires rendered content for Browser audits and incomplete exports to stay truthful. Preserve partial/source evidence for inspection, but exclude it from completed Browser audits or explicitly propagate incomplete status into every affected view/export. Avoid a source canonical being labeled rendered in this fallback (`crawl.rs:1432`).

8. **P2: browser configuration remains editable during a crawl.** `src/main.rs:1470-1475,1495-1508` leaves Choose executable active and its callback changes settings/message during an active run. Disable it and guard the callback while crawling, consistent with the disabled mode selector and the spec's fixed-run configuration.

## Standards

Missing source evidence presented as complete violates DESIGN.md's Honest Capture Rule and PRODUCT.md's “Do not add a claim the crawl did not earn.” Related maintainability heuristic: `source_note.to_ascii_lowercase().contains("truncated")` in `src/crawl.rs:1728` uses presentation prose as domain state. Use a structured source read/capture state with a separate explanation.

## Verification and limits

- Root ran temporary real-browser loopback probes with Chrome/157.0.8103.40 for missing source/noindex, canonical replacement, History API identity, and UTF-8 capture size. All four reproduced the issues above. Probe files are removed after review; add permanent regression tests that assert correct behavior.
- calmtoad-eng2 independently reviewed lifecycle, flags, navigation and resource behavior. Its simple script-only window.open probe did **not** reach the forbidden endpoint; do not report a proven popup bypass from the monitor's 750ms delay alone.
- Eng2 also launched an isolated renderer in a child process and exited that parent without destructors. Two seconds later its unique profile still existed and ten browser processes referencing that profile remained. It cleaned up only those probe-owned PIDs/profile. The desktop app uses a detached crawl worker (`src/main.rs:643-663`) and has no State/CrawlJob cancellation/join on close. This is a reproduced parent-process-exit failure, not a direct UI-close test; add explicit bounded app-close ownership and verify the real close path. Drop-based renderer cleanup alone does not cover process exit.
- Review does not establish Windows/Linux runtime support. Existing suite passing does not cover the reproduced cases. Run targeted regressions plus fmt, Clippy and the appropriate full suite after corrections, then cross-platform CI before release.
- Keep HTML default/fast and no-browser operation intact. Preserve the local-only performance policy. Do not reset benchmark baselines to hide regressions.
