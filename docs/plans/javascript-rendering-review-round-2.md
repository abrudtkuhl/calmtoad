## Remaining findings

1. **P2 — unchanged canonicals are falsely reported as changed.** `src/indexability.rs:1424-1440` still merges away a source declaration identical to the rendered declaration without preserving its capture stage. The new change comparison at `972-988` sees a nonempty rendered list versus an empty source list and reports `CanonicalChanged`. A pure reproduction through the actual `merge_canonicals` → `assess` path produced `stages=[Rendered], label=NoBlockFound, attention=true, findings=[CanonicalSelf, NoBlockFound, CanonicalChanged]` for an unchanged self canonical. Preserve complete stage observations/signatures and multiplicity where required, and add an integration regression through production merging, not only hand-built staged evidence.

2. **P1 — a URL change during settling still attributes destination DOM to the requested URL and schedules the wrong link.** `src/render.rs:1387-1398` snapshots `same_document` before the settle window. Extraction at `1436-1439` uses that stale snapshot, although the watcher later returns `Navigated`. Actual Chrome probe: after 250ms, `/history` calls `history.replaceState(null, '', '/changed/path')`, changes its title to `After`, and adds `<a href=child>`. With an 800ms settle, Capture is Navigated but contains the destination DOM. A full crawl using default settings returned `/history` with title `After` and link `/child`, fetched `/child`, then fetched `/changed/path`. The link should belong to `/changed/path` and resolve to `/changed/child`; it must not be attributed to `/history`. Recheck identity/policy after settling/source capture and extraction, discard destination DOM for interrupted jobs, and prevent destination links/canonicals from passing into the original page. Test transitions at multiple points in readiness, not only synchronous scripts before DOMContentLoaded. Apply the same reasoning to blocked later document navigations and resource-limit changes during settle.

3. **P1 — failed essential JavaScript still produces a complete capture.** `src/render.rs:1334-1340` observes loading failures but retains only main-document failures. A real fixture served a valid HTML application shell with `<script src=/broken.js>`; the script response advertised 10,000 bytes, sent one byte, and closed. Chrome returned `Captured`, empty reason, `SourceState::Captured`, and the unhydrated shell. CaptureInfo therefore considers it complete. Record resource failures with useful URL/type/error evidence and propagate incomplete essential rendering into assessment and exports. Distinguish a missing favicon from a failed application script rather than treating all resource failures identically. Add regressions for transport-failed and HTTP-error scripts and appropriately scoped resource behavior.

4. **P1 — startup is still outside cancellation/app-close ownership.** `src/crawl.rs:898` calls BrowserRenderer::launch without cancellation. `src/render.rs:547-579` launches the process, performs up to two additional five-second commands, then registers the PID. `src/main.rs:678-680` sweeps only registered browsers and does not join the detached worker. Closing during that registration gap can miss a live browser in both app-close and final-main sweeps; Stop during startup also cannot interrupt launch. Setup commands at `render.rs:973-1033` are still directly awaited without the absolute page deadline/cancel selection, and lock/context/page waits in run_job select only their deadline. The first pass fixed normal cleanup and hung evaluation, not every lifecycle phase. Coordinate owned startup with shutdown, register/process-guard early, check cancellation and apply a true outer deadline through all setup commands. Verify close/Stop during startup and setup failures, not just after launch completes. This race is supported by code inspection; no new startup-race reproduction is claimed here.

5. **P2 — incomplete Links results can still export OK.** `src/main.rs:2022-2030` suppresses completed audit claims for Titles/Meta/H1/Canonical/Images but omits Links. `2100-2103` consequently exports `OUTBOUND=—` with `ISSUE=OK` for an incomplete Browser page with no known broken destination, without capture provenance. The UI has the analogous restricted tab list. Apply incomplete handling to Links without hiding actually observed broken links or inventing healthy checks. Cover timeout, source-only and resource failure in both row display and CSV.

## Confirmed improvements and verification

- Structured SourceState and capture completeness now prevent the first-round missing-source false clean result in the inspected assessment path.
- Canonical assessment now selects a stage rather than treating source replacements as simultaneous conflicts; the merge regression above remains.
- Browser launch switches no longer have doubled prefixes; chooser changes are disabled/guarded while crawling.
- Cancellation during DOM extraction and bounded shutdown are implemented, with the setup/startup gaps above still open.
- Incomplete ordinary content audits are excluded; Links still needs the corresponding export treatment.
- Root ran two temporary actual-Chrome loopback probes (14.21s and 14.61s) reproducing failed-script capture, delayed History API DOM retention and the wrong scheduled URL. Temporary probe files were removed. Another reviewer reproduced unchanged canonical behavior through the current compiled library. No full-suite rerun was needed to establish these failures.
- OpenCode reports 90 library, 20 UI, and 19 real-browser tests passing. Those reported passes do not cover these reproduced cases. Cross-platform runtime verification is still pending.
